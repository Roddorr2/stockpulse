# Requerimientos No Funcionales — StockPulse

Cada NFR incluye una métrica verificable — un NFR sin métrica es solo una intención, no un requerimiento.

| Categoría      | ID     | Requerimiento                                                                                                | Métrica objetivo                                                                     | Cómo se verifica                                                       |
| -------------- | ------ | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Performance    | NFR-01 | Los endpoints de lectura (GET) deben responder rápido bajo carga normal                                      | p95 < 300ms con 50 usuarios concurrentes                                             | Test de carga con k6 o Apache JMeter                                   |
| Performance    | NFR-02 | El endpoint de venta (con locking) debe mantener latencia aceptable bajo contención                          | p95 < 500ms con reintentos incluidos                                                 | Test de carga dirigido al mismo SKU                                    |
| Concurrencia   | NFR-03 | El sistema no debe permitir sobreventa bajo ninguna condición de concurrencia                                | 0 casos de stock negativo en 1000 ventas simultáneas simuladas                       | Test de integración con hilos concurrentes (JUnit + `ExecutorService`) |
| Seguridad      | NFR-04 | Las contraseñas nunca se almacenan en texto plano                                                            | Hash BCrypt con factor de costo ≥ 10                                                 | Revisión de código + test unitario del hasher                          |
| Seguridad      | NFR-05 | Los tokens de acceso deben expirar rápido para limitar ventana de exposición                                 | Access token: 15 min · Refresh token: 7 días                                         | Test de integración validando rechazo post-expiración                  |
| Seguridad      | NFR-06 | El endpoint de login debe estar protegido contra fuerza bruta                                                | Rate limit: máx. 5 intentos/min por IP                                               | Test de integración simulando ráfaga de requests                       |
| Disponibilidad | NFR-07 | El sistema debe exponer un endpoint de health check para orquestadores/monitoreo                             | `GET /actuator/health` responde en < 100ms                                           | Verificación manual + incluido en CI                                   |
| Escalabilidad  | NFR-08 | El backend debe ser stateless para permitir escalado horizontal                                              | 0 uso de `HttpSession`; toda autenticación vía JWT                                   | Revisión de código                                                     |
| Mantenibilidad | NFR-09 | La capa de dominio debe mantener alta cobertura de tests                                                     | Cobertura de línea > 80% en `domain/` y `application/`                               | Reporte de JaCoCo en el pipeline de CI                                 |
| Mantenibilidad | NFR-10 | El código debe cumplir un estándar de estilo consistente                                                     | 0 violaciones críticas de Checkstyle                                                 | Gate en CI (`mvn checkstyle:check`)                                    |
| Observabilidad | NFR-11 | Los errores de negocio deben quedar logueados con contexto suficiente para debug sin exponer datos sensibles | 100% de excepciones de negocio logueadas con `traceId`                               | Revisión de logs en ambiente de `dev`                                  |
| Usabilidad     | NFR-12 | El dashboard debe reflejar alertas de stock sin necesidad de recargar la página                              | Latencia de push WebSocket < 2s desde el evento de venta                             | Prueba manual + test E2E de QA-Fortress                                |
| Portabilidad   | NFR-13 | El sistema completo debe poder levantarse en un entorno limpio con un solo comando                           | `docker-compose up --build` deja el sistema operativo sin pasos manuales adicionales | Verificación en máquina limpia / CI                                    |
